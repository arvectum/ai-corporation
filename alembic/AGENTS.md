# Alembic instructions

These rules apply to migration work under `alembic/`.

- Load the `alembic-migration` skill before changing a revision.
- Inspect current heads and the parent revision before editing.
- Review autogenerated operations manually.
- Provide explicit upgrade and downgrade behavior.
- Avoid destructive data changes without an approved backup and recovery plan.
- For new non-null fields, use a staged add/backfill/constrain sequence when required.
- Preserve PostgreSQL compatibility, naming conventions, indexes, uniqueness, foreign keys, and extension assumptions.
- Verify migration from a clean database and from the relevant previous revision when local infrastructure permits.
- Report lock risk, compatibility window, rollback limits, and manual deployment steps.
- Never include credentials or real partner/customer data.
