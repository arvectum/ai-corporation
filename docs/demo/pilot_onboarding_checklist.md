# Чек-лист управляемого onboarding пилота

Документ используется владельцем пилота Arvectum и ответственным лицом заказчика. Пилотный рабочий цикл не начинается, пока обязательные пункты не подтверждены.

## 1. Квалификация

- [ ] Определена конкретная проблема тендерного подразделения, которую проверяет пилот.
- [ ] Выбран один профиль поставщика или товарное направление.
- [ ] Подтверждено, что основной периметр — публичные закупки по 44-ФЗ.
- [ ] У заказчика есть минимум 10 реальных кейсов, из них 3 пригодны для полного ручного эталона.
- [ ] Заказчик принимает human-in-the-loop и запрет автоматических внешних действий.
- [ ] Назначены владелец пилота со стороны заказчика и владелец со стороны Arvectum.
- [ ] Согласованы срок, объём, цена и порядок завершения.

Решение квалификации: `GO / NO-GO`.

## 2. Команда и коммуникации

- [ ] ФИО и роль владельца пилота заказчика зафиксированы.
- [ ] Определены до двух операторов, участвующих в проверке.
- [ ] Определён канал для передачи документов.
- [ ] Определён канал для оперативных вопросов.
- [ ] Назначена еженедельная встреча продолжительностью 30 минут.
- [ ] Зафиксирован срок обратной связи заказчика по каждому отчёту.
- [ ] Зафиксирован порядок срочной эскалации Sev-1.

## 3. Профиль поставщика

- [ ] Юридическое наименование или внутренний идентификатор профиля.
- [ ] Категории продукции / ОКПД2.
- [ ] Ключевые слова и синонимы.
- [ ] Стоп-слова и исключённые категории.
- [ ] Регионы работы и ограничения по логистике.
- [ ] Минимальный и максимальный размер закупки.
- [ ] Целевая маржа или правила экономической оценки.
- [ ] Налоговый режим расчётов, если он влияет на экономику конкретного кейса.
- [ ] Допустимые сроки оплаты и отсрочки.
- [ ] Допустимые обеспечения, гарантии, штрафы и иные риск-ограничения.
- [ ] Требуемые лицензии, сертификаты, СРО или допуски.
- [ ] Предпочтения по поставщикам, брендам и аналогам.
- [ ] Профиль проверен и подтверждён оператором заказчика.

## 4. Входные данные и baseline

- [ ] Сформирован список минимум из 10 кейсов.
- [ ] Выбраны 3 калибровочных кейса с полным ручным разбором.
- [ ] Для каждого калибровочного кейса сохранён исходный комплект документов.
- [ ] Зафиксировано активное время ручного первичного анализа.
- [ ] Зафиксирован перечень найденных вручную критических требований.
- [ ] Зафиксирован перечень найденных вручную критических рисков.
- [ ] Зафиксировано фактическое решение оператора и его обоснование.
- [ ] Указано, какие данные отсутствовали или были нечитаемы.

Baseline считается пригодным только при наличии времени и ручного эталона по всем трём калибровочным кейсам.

## 5. Данные, безопасность и ограничения

- [ ] Заказчик получил и принял описание ограничений пилота.
- [ ] Подтверждено отсутствие подачи заявок, ЭЦП и автоматической отправки сообщений.
- [ ] Определено, какие данные могут передаваться в пилотный контур.
- [ ] Определено, какие данные требуют редактирования или обезличивания.
- [ ] Реальные документы не будут коммититься в GitHub.
- [ ] Секреты и токены не передаются в тексте задач, отчётов или логов.
- [ ] Определены срок хранения и порядок удаления пилотных данных.
- [ ] Зафиксировано, что текущие материалы не являются юридическим заключением или гарантией результата закупки.
- [ ] Зафиксировано, используется ли только утверждённый детерминированный baseline либо отдельно согласованный версионированный режим анализа.

## 6. Создание рабочего пространства

- [ ] Создан Customer с уникальным идентификатором.
- [ ] Создан PilotProject.
- [ ] Создан первый ProcurementCase.
- [ ] Проверена изоляция чтения и записи в границах заказчика.
- [ ] Проверена аутентификация пилотного контура.
- [ ] Проверено создание AnalysisRun с idempotency key.
- [ ] Проверена публикация канонического результата.
- [ ] Проверена публикация и скачивание итогового PDF.
- [ ] Проверена неизменяемая операторская проверка.
- [ ] Проверены переходы `operator_review → client_ready → delivered`.
- [ ] Проверена запись обратной связи.
- [ ] Выполнен backup/recovery preflight по действующему R9 runbook.

## 7. Калибровка

Для каждого из трёх эталонных кейсов:

- [ ] Входной комплект принят и зафиксирован.
- [ ] Анализ выполнен без внешних действий.
- [ ] Составлен список найденных системой критических требований.
- [ ] Составлен список найденных системой критических рисков.
- [ ] Выполнено сопоставление с ручным эталоном.
- [ ] Зафиксированы пропуски, ложные срабатывания и неоднозначности.
- [ ] Уточнены профиль, словари и правила, если изменение подтверждено заказчиком.
- [ ] Создан новый run после существенной корректировки; утверждённый артефакт не редактировался.
- [ ] Оператор заказчика оценил понятность и полезность отчёта.

Калибровка завершена, когда нет нерешённых Sev-1 и обе стороны одинаково трактуют критические поля scorecard.

## 8. Launch gate рабочего цикла

- [ ] Заполнен [pilot_kpi_scorecard.md](pilot_kpi_scorecard.md) для калибровочных кейсов.
- [ ] Проверены формулы и единицы измерения KPI.
- [ ] Подтверждены целевые сервисные сроки.
- [ ] Подтверждён порядок [pilot_expert_escalation.md](pilot_expert_escalation.md).
- [ ] Подтверждены [pilot_commercial_terms.md](pilot_commercial_terms.md).
- [ ] Нет нерешённых Sev-1.
- [ ] Нет неподтверждённых утверждений о точности, автономности или гарантии победы.
- [ ] Владелец пилота Arvectum разрешил переход к рабочему циклу.
- [ ] Владелец пилота заказчика подтвердил переход к рабочему циклу.

Решение запуска: `PILOT_LAUNCH_APPROVED / RETURN_TO_CALIBRATION / STOP`.
