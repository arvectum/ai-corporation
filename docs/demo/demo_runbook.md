# Runbook клиентского демо Arvectum

## 1. Назначение

Runbook обеспечивает воспроизводимый показ закупочного AI-оператора и честный переход к ARV-042. Live-источник не должен быть единственной точкой отказа: ведущий заранее готовит стабильный демонстрационный кейс и ручной fallback.

## 2. Быстрый локальный старт

```bash
cd <repository-root>
set -a && source .env.local && set +a
.venv/bin/python -m uvicorn src.main:app --host 127.0.0.1 --port 8000
```

Основная локальная точка: `http://127.0.0.1:8000/demo/tender-agent`.

В unified site/pilot deployment использовать `/pilot/tender-agent` через утверждённый proxy boundary.

## 5. Рекомендованные данные

| Параметр | Значение |
|---|---|
| Поисковый запрос | `электротехническое оборудование` |
| Закон | 44-ФЗ |
| Макс. результатов | 10 |
| Стабильный fallback | утверждённая демо-закупка из текущего fixture |
| Live fallback | ручной ввод реестрового номера |
| Источники | электронное извещение ЕИС → карточка ЕИС → прикреплённые документы |

Не закреплять в клиентском документе реальный номер закупки как вечный fallback: он может измениться, исчезнуть или перестать соответствовать сценарию. Актуальный fixture проверяется перед каждой встречей.

## 6. Fallback-сценарии

### ЕИС не отвечает или HTML изменился

- показать честный статус источника;
- открыть стабильную демо-закупку;
- при необходимости вручную найти закупку и вставить номер;
- не пытаться обходить captcha или имитировать личный кабинет.

### Read-only источник не возвращает архив

- перевести сценарий в ручную загрузку;
- показать, что система не продолжает анализ без принятого комплекта;
- объяснить, что ожидание/неполнота фиксируются отдельно от времени работы оператора.

### Credentials не настроены

- не вводить секрет во время демонстрации на экране;
- использовать локальный fixture и ручную загрузку;
- после встречи настроить секрет через утверждённую runtime-конфигурацию.

### Документ повреждён или нечитаем

- пометить комплект неполным;
- не выдавать спорный вывод как подтверждённый;
- показать ручную экспертную эскалацию;
- Sev-1 должен блокировать `client_ready`.

### Итоговый артефакт не проходит проверку

- не скачивать и не передавать непроверенный PDF;
- не импортировать filesystem-only файл как принадлежащий заказчику;
- создать новый корректный run либо остановить кейс;
- не демонстрировать ручное редактирование утверждённого артефакта.

## 8. Приоритет и конфликт источников

Приоритетным структурированным источником является электронное извещение. Метаданные карточки поиска используются как fallback, а прикреплённые документы — для детального анализа. Конфликт источников не разрешается скрыто: он фиксируется как `source_mismatch`, а критический конфликт направляется на эскалацию.

В отчёте должны быть различимы:

- подтверждённый факт;
- расчёт;
- интерпретация;
- неизвестное или отсутствующее значение.
