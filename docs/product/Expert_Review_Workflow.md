# ARV-052 — продуктовый workflow экспертной проверки

Статус: `ARV_052_COMPLETE`.

## Назначение

Workflow подключает специалиста Arvectum только к сложному или рискованному
отчёту. Он расширяет обязательную операторскую проверку, но не заменяет её и не
открывает внешние действия. Любой результат остаётся консультационным; решение
об участии и действия на ЭТП выполняет заказчик.

## Область действия

Экспертная карточка всегда привязана к точной области
`Customer → Project → ProcurementCase → AnalysisRun`. Создание разрешено только
для текущего завершённого run в статусе `operator_review` и до immutable
операторского verdict.

Поддерживаются три уровня:

| Уровень | Блокировка | Цель начала проверки |
|---|---|---|
| `sev1` | блокирует `client_ready` и доставку | 4 рабочих часа |
| `sev2` | блокирует `client_ready` и доставку | 9 рабочих часов / следующий рабочий день |
| `sev3` | не блокирует кейс | 45 рабочих часов / weekly review |

Расчёт выполняется по будням 09:00–18:00 Europe/Moscow. Это внутренний
сервисный ориентир `arv052-business-hours-v1`, а не публичный SLA.

## Детерминированные триггеры и роли

Карточка принимает только версионированные trigger codes. Для каждого кода
заранее определена требуемая роль: procurement, legal, commercial, technical,
security или quality lead. `quality_lead` может принять любой кейс; назначение
несоответствующей роли отклоняется.

Коды покрывают отсутствие и нечитаемость документов, противоречия,
непрослеживаемый evidence, влияние на решение об участии, коммерческие условия,
обязательные допуски, неподтверждённую экономику, критически низкую уверенность,
расхождение оператора и системы, safety/tenant incident и подтверждённую ошибку
Arvectum.

## Состояния

`awaiting_commercial_approval → open → assigned → in_review`

Из `in_review` возможны:

- `awaiting_customer` с последующим возвратом в `assigned`;
- `resolved` для `CONFIRMED`, `REJECTED`, `NEEDS_NEW_RUN`;
- `blocked` для `BLOCK_CASE`.

Финальные решения неизменяемы. Для пересмотра создаётся новый run и новая
карточка. `NEEDS_NEW_RUN` возвращает кейс в `operator_review`, после чего
существующий idempotent run endpoint создаёт новый анализ. `BLOCK_CASE`
архивирует кейс.

## Решения эксперта

Допустимы только:

- `CONFIRMED`;
- `REJECTED`;
- `NEEDS_CUSTOMER_INPUT`;
- `NEEDS_NEW_RUN`;
- `BLOCK_CASE`.

Для `REJECTED`, `NEEDS_NEW_RUN` и `BLOCK_CASE` обязательна категория feedback.
Система автоматически создаёт `PilotFeedback`, связанный с исходным run, чтобы
исправление попало в quality loop. Уровень обратной связи нормализуется в
`critical/high/low` из `sev1/sev2/sev3`.

`sev3` не может потребовать новый run или заблокировать кейс без отдельной
эскалации более высокого уровня.

## Аудит

Каждое действие создаёт:

1. metadata-only `PilotAuditEvent` без документов, секретов и заголовков;
2. append-only событие карточки с sequence number;
3. SHA-256 hash chain `previous_event_hash → event_hash`.

Read endpoint пересчитывает цепочку и возвращает `chain_valid`. Редактирование и
удаление событий через API отсутствуют. Hash chain выявляет изменение записи,
но не заменяет права доступа, резервное копирование и внешний WORM-аудит.

## Коммерческая логика

В стандартный пилот включены первые три `sev1/sev2` проверки проекта. `sev3` не
расходует этот лимит. Четвёртая и последующие проверки создаются как
`paid_addon` с зафиксированной гипотезой 3 000 ₽ и не могут быть назначены до
явного `approve` или `waive`.

Safety/tenant incident и подтверждённая ошибка Arvectum всегда имеют режим
`safety_no_charge`. Workflow фиксирует коммерческое решение, но не выставляет
счёт, не принимает оплату и не заменяет будущий usage/billing ledger ARV-068.

## Граница ролей

Поля actor/actor_role и expert/expert_role создают аудируемый внутренний
контракт. Связывание этих значений с реальным authenticated principal и
полноценный RBAC относятся к ARV-043. До этого endpoint остаётся внутри
существующей operator-auth границы `/api/operator/pilot`.

## Non-goals

ARV-052 не реализует юридическое заключение, гарантию допуска/победы,
автоматическую подачу, ЭЦП, отправку писем, оплату, публичный SLA, круглосуточную
поддержку или автономное исправление утверждённого PDF.
