# ARV-067 — электротехническая онтология v1

Статус: `RESEARCH_ASSET_READY`

## 1. Зачем нужен этот слой

Общая языковая модель может извлечь похожие слова, но для подбора закупок и
аналогов этого недостаточно. В электротехнике совпадение категории не означает
взаимозаменяемость: материал жилы, число жил, сечение, напряжение, характеристика
расцепления, отключающая способность или напряжение катушки могут быть
обязательными разделителями.

ARV-067 вводит версионируемый контракт данных, который позволяет отдельно
проверять:

- распознавание категории и синонимов;
- полноту обязательных характеристик;
- правила `exact`, `minimum`, `maximum`, `contains`;
- объяснимые причины несовпадения;
- пять итогов: `EXACT`, `LIKELY_ANALOG`, `PARTIAL`, `UNCERTAIN`, `NO_MATCH`.

Это подготовительный data asset. Production resolver, модели БД и миграции в
задаче не меняются.

## 2. Покрытие v1

| Категория | Обязательные разделители | Примеры нормализуемых обозначений |
|---|---|---|
| Силовой кабель низкого напряжения | материал жилы, число жил, сечение, напряжение, материал изоляции | АВВГ-П, АВВГнг(А)-LS, ВВГнг(А)-LS |
| Самонесущий изолированный провод | материал жилы, число жил, сечение, напряжение | СИП-1…СИП-5 |
| Модульный автоматический выключатель | полюса, номинальный ток, кривая, отключающая способность, напряжение, род тока | 1P/3P, B/C/D, 6/10 кА |
| Электромеханический контактор | полюса, рабочий ток, напряжение и род тока катушки, категория применения | AC-1/AC-3/AC-4, 24 V DC, 220 V AC |

## 3. Принцип сравнения

Проверка идёт в фиксированном порядке:

1. категория;
2. наличие запрошенных обязательных полей;
3. совместимость обязательных полей;
4. совместимость опциональных полей;
5. совпадение канонической марки.

Семантика числовых полей задаётся в схеме, а не угадывается моделью. Например:

- сечение, число жил, ток автомата, кривая и напряжение катушки сравниваются
  точно;
- напряжение кабеля, отключающая способность автомата и рабочий ток контактора
  являются минимальной требуемой способностью: кандидат может иметь большее,
  но не меньшее значение;
- требуемый набор вспомогательных контактов должен содержаться в наборе
  кандидата.

Если обязательное значение отсутствует, результат — `UNCERTAIN`. Он не
повышается до аналога без evidence.

## 4. Объяснимость

Стабильные reason codes отделяют отсутствие данных от доказанного
несоответствия. Ключевые примеры:

- `CATEGORY_MISMATCH`;
- `REQUIRED_ATTRIBUTE_MISSING`;
- `EXACT_VALUE_MISMATCH`;
- `MINIMUM_CAPABILITY_INSUFFICIENT`;
- `OPTIONAL_VALUE_MISMATCH`;
- `CANONICAL_MARK_DIFFERS`.

Эти коды предназначены для будущего evidence-backed UI и benchmark-отчётов, но
в production пока не подключены.

## 5. Источниковая рамка

Словарь параметров и границы категорий сверены с действующими карточками
стандартов и отраслевой номенклатурой:

- ГОСТ 31996-2012 — силовые кабели с пластмассовой изоляцией на 0,66; 1 и 3 кВ;
- ГОСТ 31946-2012 — самонесущие изолированные и защищённые провода для ВЛ;
- ГОСТ IEC 60898-1-2020 — автоматические выключатели переменного тока бытового
  и аналогичного назначения;
- ГОСТ IEC 60947-4-1-2021 — электромеханические контакторы и пускатели.

Ссылки на карточки и роль каждого источника записаны внутри ontology YAML.
Стандарт задаёт терминологическую основу, но сам по себе не доказывает
эквивалентность конкретного товара и не заменяет техническую документацию
изготовителя.

## 6. Fixtures и gate

Пакет содержит:

- 8 synonym cases;
- 13 match cases;
- покрытие всех пяти итоговых labels;
- positive и negative cases для АВВГ-П, СИП-4, автоматов и контакторов;
- отдельный manifest с определениями category recall, attribute recall,
  false-match rate и uncertain rate.

Проверка:

```bash
python schemas/categories/electrical/validate.py
python -m pytest -q tests/test_arv067_electrical_ontology.py
```

Fixture-набор подтверждает консистентность контракта, но не является заявлением
о качестве production extraction. Для реальных метрик нужны замороженные и
независимо проверенные truth packs из ARV-001/ARV-005.

## 7. Следующий безопасный шаг

После появления accepted output ARV-003 и quality gate ARV-001 можно сделать
отдельную задачу productionization:

1. выбрать формат загрузки схемы и версионирование;
2. реализовать resolver adapter без изменения смысла полей;
3. прогнать реальные электротехнические закупки;
4. измерить category recall и false-match rate;
5. подключать ontology только после прохождения gate и миграционного плана.

Маркеры результата:

- `ARV-067_ELECTRICAL_ONTOLOGY_READY`
- `ARV-067_SCHEMA_AND_FIXTURES_VALIDATED`
- `ARV-067_PRODUCTION_RUNTIME_NOT_WIRED`
